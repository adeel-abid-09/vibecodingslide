📖 Lesson Vocabulary & Core Terminologies

Essential technical jargon explained in plain English for beginners:

API (Application Programming Interface)
A defined digital contract of rules and endpoints that allows two separate software systems (like a React browser and an Express server) to talk to each other.
REST (Representational State Transfer)
The industry-standard architectural style for building web APIs using standard URLs and HTTP methods.
Endpoint
A specific URL path on a server that performs a specific action (e.g. `http://localhost:5000/api/products`).
HTTP Verbs (Methods)
The 4 primary action words of the web: GET (read), POST (create new), PUT (update existing), and DELETE (remove).
HTTP Status Codes
Standardized 3-digit numbers telling the client what happened: 2xx (Success), 3xx (Redirect), 4xx (Client mistake/missing data), 5xx (Server crashed).
Request Body (Payload)
The JSON data package sent inside a POST or PUT request from the client to the server.
URL Parameter (`:id`)
A dynamic placeholder in a route path (`/api/items/:id`) used to target a specific record, accessed via `req.params.id`.
Query String (`?search=term`)
Key-value pairs appended to the end of a URL after a `?` used for sorting, filtering, or searching, accessed via `req.query`.

✅ The Non-Negotiable Key Takeaways

  • ✔
    HTTP Verbs Dictate Action: A URL like `/api/tasks` reads with `GET`, creates with `POST`, and removes with `DELETE`.
  • ✔
    Status Codes Tell the Truth: `200/201` means success, `400` means bad client input, `404` means not found, `500` means server crashed.
  • ✔
    `req.params` vs `req.body`: `req.params.id` grabs values directly from the URL (`/api/items/99`); `req.body` carries complex JSON objects sent with POST/PUT.
