📖 Lesson Vocabulary & Core Terminologies

Essential technical jargon explained in plain English for beginners:

NoSQL Database
A non-relational database that stores data as flexible, JSON-like documents rather than rigid tables with rows and columns.
Document
A single record in a MongoDB collection (analogous to a row in SQL or a single JSON object), automatically assigned a unique `_id`.
Collection
A grouped folder of documents inside MongoDB (analogous to a table in SQL, e.g. the "users" collection or "products" collection).
ObjectId
A unique 24-character hexadecimal identifier automatically generated by MongoDB for every single document to guarantee uniqueness.
Mongoose
An ODM (Object Data Modeling) library for Node.js and MongoDB that acts as a strict building inspector, enforcing schemas, data types, and validations.
Schema
The blueprint that defines the shape, rules, required fields, and default values of documents in a Mongoose collection.
Model
The compiled constructor compiled from a Schema that provides methods to create, query, update, and delete documents (e.g. `User.find()`).
Environment Variables (`.env`)
Hidden system variables stored outside your source code used to keep private passwords, database URIs, and secret keys safe from being published to GitHub.

✅ The Non-Negotiable Key Takeaways

  • ✔
    Collections & Documents: A Collection is a folder of records; each record is a JSON-like Document with a unique `_id`.
  • ✔
    Mongoose is the Guard: It enforces schemas so bad or incomplete data cannot corrupt your database.
  • ✔
    `.env` Protection: Never commit passwords or `MONGO_URI` to GitHub. Always put `.env` inside `.gitignore`.
