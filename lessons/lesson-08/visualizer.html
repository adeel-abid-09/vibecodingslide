📐 The JWT Verification Lifecycle

sequenceDiagram
    autonumber
    actor User as User Browser
    participant Auth as POST /api/auth/login
    participant Middleware as authMiddleware.js
    participant Route as GET /api/user/profile

    User->>Auth: Submit credentials (email, password)
    Note over Auth: bcrypt.compare() validates hash
    Auth-->>User: Issues JWT Token (Signed with JWT_SECRET)
    User->>Middleware: GET /api/user/profile with Header: Bearer 
    Note over Middleware: jwt.verify(token, JWT_SECRET)
    alt Valid Token
        Middleware->>Route: next() passes request through
        Route-->>User: HTTP 200 OK + Profile JSON
    else Invalid or Missing Token
        Middleware-->>User: HTTP 401 Unauthorized
    end

📖 Lesson Vocabulary & Core Terminologies

Essential technical jargon explained in plain English for beginners:

Authentication (AuthN)
Verifying "Who are you?" by checking user identity through credentials like an email and password.
Authorization (AuthZ)
Verifying "What are you allowed to do?" (e.g. Can this user delete a post, or only view it? Are they an admin?).
Plain-Text Password
An unencrypted password written exactly as typed (e.g. "secret123"). Storing plain text in a database is a dangerous security violation.
Bcrypt Hashing & Salt
A one-way cryptographic mathematical function that scrambles passwords into an irreversible string, combined with random characters (Salt) to prevent rainbow-table attacks.
JWT (JSON Web Token)
A compact, URL-safe digital token formatted as `header.payload.signature` that acts as a tamper-proof VIP wristband verifying a logged-in user.
Bearer Token
The industry-standard format for passing JWT tokens inside the HTTP `Authorization` request header: `Authorization: Bearer `.
Auth Middleware (Guard)
A gatekeeper function that checks if an incoming request contains a valid, unexpired JWT signed with `process.env.JWT_SECRET` before allowing access to private routes.

✅ The Non-Negotiable Key Takeaways

  • ✔
    Bcrypt One-Way Hashing: Passwords are never stored as plain text. They are hashed so that even the database admin cannot see the user's password.
  • ✔
    JWT is a Wristband: It contains the user's ID inside its payload, signed with a secret key so it cannot be tampered with.
  • ✔
    Middleware Gatekeeper: Placing `protect` inside `router.get('/profile', protect, getProfile)` stops unauthorized users before they ever touch sensitive data.
